# Laptop Asset Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three PC-style laptop furniture assets in beige, graphite, and silver, then verify they load and render correctly in the editor/runtime.

**Architecture:** Author the laptop as three separate furniture families because the current manifest/catalog system keys rotation and state behavior by a single `groupId`, which cannot represent multiple color subfamilies inside one rotation/state family without collisions. Each family will mirror the current `PC` structure: `front` carries `off` plus animated `on` frames, while `back` and `side` are state-independent. The `PC` asset in this codebase uses `footprintW: 1` and `footprintH: 2`, so the laptop should match that exact footprint to preserve PC-style behavior. The shared asset source of truth remains `webview-ui/public/assets/furniture`, with build output generated by the existing Vite/esbuild pipeline.

**Tech Stack:** TypeScript, Vite, esbuild, JSON furniture manifests, PNG sprite assets, Node test runner
